## pi

pi (`brew "pi-coding-agent"`, 1.5.0) has no XDG handling: `dist/config.js` builds every path from `join(homedir(), ".pi", "agent")` unless `PI_CODING_AGENT_DIR` is set, and upstream closed the XDG request as wontfix ([earendil-works/pi#2870](https://github.com/earendil-works/pi/issues/2870)), so the two variables in `env.fish` are the permanent answer — `PI_CODING_AGENT_DIR=$XDG_CONFIG_HOME/pi` (settings, models, `auth.json`, prompts, themes) and `PI_CODING_AGENT_SESSION_DIR=$XDG_DATA_HOME/pi/sessions`. Sessions go to DATA, not STATE. The spec's STATE is for what is "not important or portable enough to the user" for DATA — "actions history" and undo history are its examples — and pi treats sessions as the opposite: never pruned (no retention setting exists; `PI_CACHE_RETENTION` is provider prompt caching), compaction keeps the original entries, abandoned branches survive, and sessions are named, searched, forked, cloned, exported and shared (pi's upstream session documentation). STATE was the first choice, reasoned from the "actions history" example alone; a cold question to Codex and then pi's own docs both pointed to DATA, and OpenCode keeps its sessions there too. Verified on first run: `auth.json` and `models-store.json` landed in `~/.config/pi`, and `~/.pi` was never created. Its `fd`/`rg` downloader checks `PATH` first, so with both in the brewfile nothing is downloaded into the agent dir's `bin/`. Like the Go variables, these reach only processes started from fish.

`settings.json` stays local for the same reason as Claude's and Codex's: pi writes it itself (`writeFileSync`, so a stowed link would survive, but the writes would land in this public repo), including a `deviceId` that regenerates when removed, a `lastChangelogVersion` that changes on every upgrade, and the `packages` list `pi install` maintains. Its hand-set values are listed in `.pi/skills/manual-setup/SKILL.md`: `shellPath` (pi's `bash` tool otherwise runs `/bin/bash` 3.2, and models routinely write bash 4+ — `brew "bash"` is in the brewfile for that; verified `$BASH_VERSION` 5.3), `defaultProvider`/`defaultModel`, `modelThinkingLevels`, and `theme` (`docs/pi-ui.md`). `auth.json` and `trust.json` are credentials and a per-directory decision, also local.

### pi is the harness; Claude Code is a backend, Codex CLI is not (decided 2026-11-10)

The main session runs on `anthropic/claude-fable-5-2` (company API key, `auth.json`; 5.2 appeared in the catalog on 2026-11-11 at $8/$40 against 5.1's $10/$50, otherwise identical). When that credit runs out the user switches by hand with `/model` to `claude-code/claude-fable-5-2` — the Claude subscription through the `pi-claude-code` package — and types "continue". An extension that did the switch automatically was written, tested with a bogus key, and removed the same day: the main session always has a person in front of it, and 40 lines whose trigger text had never been seen for real were not worth keeping. OpenAI models use the ChatGPT subscription (`/login openai`, `openai` provider, `oauth` in `auth.json`); the old `openai-codex` provider is legacy and not used. Codex CLI itself has no role in pi. Claude Code and Codex CLI are both still installed and runnable on their own.

**`pi-claude-code` over `pi-claude-bridge`.** Both use the Claude subscription through the `claude` binary. The bridge (elidickinson) runs Claude Code through the Agent SDK with Claude Code's own system prompt in front and pi's prompt as appended sections, loads `~/.claude` settings and hooks, and mirrors pi's history into Claude Code session files — faithful to Claude Code, which is exactly what pi was adopted to escape. The official one (earendil-works) runs `claude -p --system-prompt-file <pi's prompt> --tools "" --setting-sources "" --strict-mcp-config --disable-slash-commands --max-turns 1 --no-session-persistence` with `CLAUDE_CODE_DISABLE_AUTO_MEMORY`, `CLAUDE_CODE_DISABLE_CLAUDE_MDS`, `DISABLE_AUTO_COMPACT`, `ENABLE_TOOL_SEARCH=false` and telemetry off, through a loopback relay that rebuilds every user message from pi's history and strips Claude Code's reminders. Measured on 2026-11-10 by pointing `ANTHROPIC_BASE_URL` at a local capture server and running `claude` 2.1.311 with that argument set: the `system` array is three blocks — a one-line `x-anthropic-billing-header`, the sentence "You are a Claude agent, built on Anthropic's Claude Agent SDK.", and pi's prompt verbatim — plus one `role: system` message of about 250 tokens (cwd, platform, OS, a note on untrusted downloads, model name and cutoff, date) that the relay keeps in a stable position; `tools` is empty. The `<system-reminder>` with the account email that Claude Code adds to the first user message is what the relay removes. So the subscription path costs one sentence and one small fixed message over the API path. Its usage-credit guard reads `rate_limit_event.isUsingOverage` and fails the turn rather than paying extra usage. pi's own `/login anthropic` OAuth is not used: pi's code says third-party harness usage under subscription auth "draws from extra usage and is billed per token", so it has no advantage over the API key.

### User-level context file

The subagent extension, its agents, background tasks and model fallback are in `docs/pi-subagents.md` (split from this file on 2026-11-12, when it reached 24.7 KB and the subagent material was about to pass half of it; this file now loads for the user-level context file and `.pi/extensions/`, that one for the extension and the agent files).

`~/.config/pi/AGENTS.md` (stowed) is the user-level context file: the language rule and the rtk note, nothing about delegation. It loads in subagent children too.

User-level harness is mechanism, not policy (decided 2026-11-11). The `## Orchestration` section ("You are the orchestrator…", when to delegate, verify the report before relaying) was deleted; the delegation tool (`subagent` then, `task` since 2026-11-12) stays as an available mechanism, as an operating system offers system calls and leaves policy to what runs above it. Reasons: (1) delegation should be optional, not the default working mode, and an always-loaded "You are the orchestrator" made it the default in every session; (2) policy changes faster than mechanism and tying them together makes each change disturb the other — Eric Raymond, *The Art of Unix Programming*, [Rule of Separation](http://www.catb.org/~esr/writings/taoup/html/ch01s06.html), with the cost he names, "when the user can set policy, the user must set policy" ([ch01s04](http://www.catb.org/~esr/writings/taoup/html/ch01s04.html)); (3) the costs are accepted: without the section the main session delegates only when asked or when it judges the tool description applies, so work reaches the owner's own OpenAI subscription only then, and "a subagent's report is raw material, verify the claim that matters most before relaying" is no longer always in context. In its place each result now carries the subagent's session id, so the full transcript can be inspected; whether to inspect is left to the reader. Rejected the same day: an opt-in orchestrator mode as a skill or prompt template (a mechanism was wanted, not a mode); a reminder to verify in the tool description or in each result (that is policy, and a reminder on every result becomes noise); a community package (the reasons are in `docs/pi-subagents.md`).

### Path-scoped documentation and skills

**`AGENTS.md` as a map (2026-11-11).** Slimmed from about 11.5 KB (11,529 bytes) to 8,989 bytes: only what the repo is, the index, rules for any change, and warnings whose trigger touches no documented path. The test for each paragraph was “would someone who needs this read or edit a covered file first?” A new `docs/setup.md` took the bootstrap/stow/`just etc` material because nothing existing fit (`docs/homebrew.md` is about Homebrew). The “Loads when editing” column was kept and is now checked against frontmatter because Claude Code and Codex get no injection and it is their only map from path to document. Covers was extended rather than condensed because the index is the main way a document gets read: [Vercel's eval](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals) (2026-01-27) passed 100% with a docs index in `AGENTS.md`, against 53% with an on-demand skill.

`scripts/check-docs.py` enforces the three rules stated at the end of `AGENTS.md` (`just check-docs` runs it alone). References are checked in `AGENTS.md`, `README.md`, `docs/*.md` and `.pi/skills/**/*.md`, and duplicate index rows are rejected too.

**Document updates are asked for, not triggered (decided 2026-11-11).** A script mapping each git diff to the documents whose `paths` cover it, a rule in `AGENTS.md` to run it before finishing, an end-of-turn hook, and a skill for the workflow were all designed and declined. A document update belongs to a finished piece of work — a decision reached, an investigation concluded — which spans several commits or has none (a rejected alternative, a measurement that changed nothing), so the diff is the wrong trigger; [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) says the same of entries and commits. What is done instead: the owner asks, the model drafts from the conversation and the diffs, each change with its reason, and the owner approves before it is written — the shape of Anthropic's [`/revise-claude-md`](https://raw.githubusercontent.com/anthropics/claude-plugins-official/main/plugins/claude-md-management/commands/revise-claude-md.md). It is a project's workflow, so nothing about it sits at user level, and it is not a skill here until a second project wants the same. The first such round, on 2026-11-11, found five decisions of that day that had no diff and so no record, this one among them.

**Documentation in `docs/` (decided 2026-11-11).** These files are documentation, not rules: a flat, visible `docs/` serves human readers as well as agents and is harness-neutral — changing harness already moved them once, from `.claude/rules/` to `.pi/rules/` on 2026-11-11. Prior art: OpenAI's [Harness engineering](https://openai.com/index/harness-engineering/) (2026-02-11), with a short `AGENTS.md` as the table of contents and `docs/` as the system of record. Rejected: `docs/rules/` (an extra layer of convention; docs live in `docs/`, the rest is up to the project); `docs/` as the root marker (too common — a nested directory's own `docs/` would pick the wrong root and break every glob); `.pi/` as the root marker (ties the location back to the harness). The root is the git root. `docs/**` was in this file's `paths` for part of 2026-11-11 and was removed: every edit to any document injected this whole file, about 13 KB, for a one-word change to `docs/env.md`, and what someone editing a document needs to know about loading is the short paragraph in `AGENTS.md`. Two more globs were narrowed on 2026-11-12 for the same reason: this file's `.pi/**` became `.pi/extensions/**`, because loading either skill with `read` injected all of it, about 2,000 words, for a colour change; and `docs/env.md`'s `config/fish/**` became `conf.d/env.fish` and `functions/wget.fish`, because a prompt or theme edit loaded its 1,200 words beside `docs/fish.md` and `docs/fish-prompt.md`. Injection timing, glob semantics, batching and once-per-session/block-on-first-edit behaviour stay unchanged; redesigning loading is a later step.

pi has no path-scoped rules. `.pi/extensions/rules.ts` reproduces Claude Code's `paths` frontmatter: at `session_start` it walks up from cwd (inclusive) to the nearest ancestor holding `.git` (file or directory, including worktrees and submodules), reads `docs/*.md` non-recursively (no `docs/` means no rules), parses each file's `paths` globs (own glob→regex, no `minimatch` for extensions; a trailing `**` must become `.*`, the first version matched nothing), and on `read`/`edit`/`write` of a matching path injects the rule once per session as a `rule` custom message. `edit`/`write` are blocked the first time with a reason telling the model the rule is already in context — the first wording, "Read it, then retry", made the model `read` the file as well, doubling the tokens. Resume re-reads injected ids from the branch; `fs.watch` on `docs/` reloads on change and re-arms only the rules whose body changed; a root watcher handles creation or removal of `docs/` and refreshes the watchers.

**All rules hit by one tool batch go out as one message**, flushed with `setTimeout(0)` after the batch's `tool_call` preflights. The first version sent one message per rule, and pi's default `steeringMode: "one-at-a-time"` delivers queued steer messages one per turn — so a scout whose spot-check batch read fish, ghostty and tmux config got one rule with the tool results, wrote its report, and then received the other three one turn at a time, answering each with "Noted; this tmux rule was included in the audit." The subagent tool takes the last assistant text, so the orchestrator saw "Noted" and not the 5,000-character report that was two messages earlier. It happened twice with terra and not with sol only because of where the spot-check landed in the sequence; the session files under `PI_CODING_AGENT_SESSION_DIR` are what made the cause visible.

Skills in `.pi/skills/` are discovered by pi natively. Both directories were `.claude/rules/` and `.claude/skills/` until 2026-11-11, read by pi through a `RULE_DIRS` entry and a `.pi/settings.json` pointing `skills` at `../.claude/skills`; they moved to `.pi/rules/` and `.pi/skills/` once pi was the only harness used here, and the documents moved on to `docs/` the same day. Claude Code and Codex see the documents only if they open them.

Project resources under `.pi/` need project trust: `-p` cannot ask, so the first two headless tests ran without the extension while the model reported rules "loaded" from the table in `AGENTS.md`; `trust.json` now holds the decision and `pi -p -a` approves for one run.
