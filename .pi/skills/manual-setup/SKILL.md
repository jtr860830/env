# Manual Setup

Steps `just setup` cannot perform — local UI state, app preferences and licences:

- **macOS settings** — Dock, Finder, key repeat, screenshots, hostname and DNS are not managed. They persist on this machine; a new one sets them by hand, and the last declared values are `darwin/system.nix` in git history.
- **OmniWM** — permissions (Accessibility, Input Monitoring, Screen Recording), Start at Login and the OmniShell bar profile, see `docs/omniwm.md`. Trackpad: turn off macOS's three- and four-finger swipes (System Settings → Trackpad → More Gestures), which OmniWM's gestures replace.
- **pi** — hand-set values in `~/.config/pi/settings.json` (see `docs/pi.md`): `"shellPath": "/opt/homebrew/bin/bash"`; `"defaultProvider": "anthropic"`, `"defaultModel": "claude-fable-5-2"` (when the API credit runs out, `/model` to `claude-code/claude-fable-5-2` by hand); `modelThinkingLevels` — `high` for fable-5-2, fable-5-1 and opus-5-5, `medium` for sonnet-5-5 and gpt-6.1-sol, `low` for haiku-5-5, gpt-6.1-terra and gpt-6-luna, each Anthropic model under both `anthropic/` and `claude-code/` so a provider switch keeps the depth. Log in with `/login anthropic` (API key) and `/login openai` (Sign in with ChatGPT). Packages, recorded in that file's `packages` list by `pi install`: `https://github.com/earendil-works/pi-claude-code` (needs `claude auth login` done in Claude Code) and `npm:pi-web-access` (no key; default `toolActivation: "auto"` declares only `web_enable`, about 100 cached tokens a request). `/trust` once in this repo so `.pi/` loads, including for subagent children; the decision lives in `~/.config/pi/trust.json`.
- **rtk** — `rtk init -g`, `rtk init -g --codex` and `rtk init -g --agent pi`. Each writes local files only (`~/.config/claude/RTK.md` and a `PreToolUse` Bash hook in `settings.json`; `~/.config/codex/{AGENTS.md,hooks.json,RTK.md}`; `~/.config/pi/extensions/rtk.ts`), except the `@RTK.md` line it appends to the stowed Claude `CLAUDE.md`, which is committed. `RTK.md` is what tells the agent its output is condensed and that `rtk bypass <cmd>` returns it raw, so `--hook-only` is not used. The pi install writes no such file — only the extension — so the same eight lines, plus `rtk recall`, are hand-copied into the stowed `config/pi/.config/pi/AGENTS.md` as `## Command Output` (added 2026-11-11, from rtk 1.2.0's `RTK.md`); an rtk upgrade that rewords `RTK.md` does not update that copy. **Answer no to "Delegate oversize reads to a cheaper model"**: it writes a `pipeline.toml` extending `rtk:delegate-reads`, which routes any whole-file read over 350 lines to that model, sending the file out and keeping it from the agent, and it lies inert only until `GEMINI_API_KEY` happens to be set. It was accepted once on 2026-11-03 and removed; with no `pipeline.toml` rtk is on `rtk:default` (`rtk pipeline status`). The telemetry prompt is moot — the Homebrew build has no telemetry endpoint (`rtk telemetry status`).
- **Claude Code** — `CLAUDE_CONFIG_DIR=~/.config/claude` is set in `conf.d/env.fish`; the one stowed file there is the user-scope `~/.config/claude/CLAUDE.md` (a writable link into the repo, so `#` and `/memory` edit the repo file; the repo is public, so its contents are too), while `~/.config/claude/settings.json` is written by the tool (`/plugin`, `enabledPlugins`, usage counters) and stays local. Its hand-set values: `pluginConfigs["cc-plugin-agents-md@builtin"].options.instructionFiles = "claude-md-and-agents-md"` — Claude Code's default, `claude-md-or-agents-md`, loads a project's `AGENTS.md` where `CLAUDE.md` would go **but only when there is no `CLAUDE.md`** (verified with a canary string in a scratch repo: `AGENTS.md` alone is read; add any `CLAUDE.md` beside it and `AGENTS.md` is silently ignored), and `/init`, `/revise-claude-md` and the `#` shortcut all write `CLAUDE.md` by name; with this value a stray `CLAUDE.md` loads *beside* `AGENTS.md` instead of replacing it (two canaries, one per file, both answered). `instructionFiles` is not a top-level key: it is the `USER_CONFIG` of the built-in plugin `cc-plugin-agents-md`, gated by the `tengu_agents_md_mod` flag, and built-in plugin options live under `pluginConfigs.<id>@builtin.options`. The user-scope file keeps the name `CLAUDE.md` because at user scope Claude Code reads only that — its built-in Codex importer copies Codex's `AGENTS.md` *into* Claude's user `CLAUDE.md`, which it would not need to do otherwise. `autoMemoryEnabled` and `autoDreamEnabled` set to `false`, so `~/.config/claude/projects/<cwd>/memory/` is neither read nor written. The `remember` plugin uninstalled (`claude plugin uninstall remember@claude-plugins-official`) — disabling was not enough: hooks load at session start, so the session that disabled it still fired its `SessionEnd` hook on exit and recreated `.remember/`; it kept a per-project `.remember/` store (self-ignoring via a `.gitignore` containing `*`), injected it at `SessionStart`, kept spawn records under `REMEMBER_RUNTIME_DIR` (that variable left `env.fish` with it), and its background summarizer ran Claude in temp directories, leaving ~660 empty entries under `~/.config/claude/projects/`. `syncClaudeAiSkills` set to `false` — the 14 skills claude.ai syncs into `~/.config/claude/skills/synced/` cost about 2,000 tokens of descriptions per session and only `docx` was ever used (3 times, all in work projects), so nothing replaces them: when a Word, Excel, PowerPoint or PDF job comes up, copy that one skill's directory from anthropics/skills into the project's `.pi/skills/` for the duration. The `document-skills` plugin was tried and rejected on 2026-11-10: its marketplace manifest names those four, but Claude Code loads all 19 skills in the repo regardless, and `skillOverrides` does not reach plugin skills under either `document-skills:<name>` or `<name>` (verified with headless `claude -p` runs listing the loaded skills). Also in that file, from a token audit on 2026-11-10 of 532 session transcripts: `enableArtifact: false` (the Artifact tool's definition is about 5,500 tokens a turn, the largest single one, and it was called once), `disableBundledSkills: true` (no built-in skill was ever invoked by hand; `code-review`, `init` and the rest were only ever picked by the model, and the superpowers plugin covers the same ground — `/init` and `/doctor` stay typable) and `disableWorkflows: true` (never used, about 1,100 tokens). `CLAUDE_CODE_SEND_FEEDBACK=0` is in `conf.d/env.fish` for the same reason (one call ever, about 1,100 tokens). `skillOverrides` was not used because `disableBundledSkills` already removes the lot.
- **Codex** — `CODEX_HOME=~/.config/codex` is set in `conf.d/env.fish`, and **Codex refuses to create it**: verified against 0.154.0, which prints `CODEX_HOME points to …, but that path does not exist` and degrades (`codex doctor`: `config could not be loaded`), so `config/codex/.config/codex/.keep` exists for `just link` to create the directory. `~/.config/codex/config.toml` is written by the tool (`codex mcp`, `codex plugin`) and stays local; its one hand-set value is `[features] memories = false` — `codex features list` shows `memories` stable but off, and this pins it against a default flip. Codex is installed so that openai/codex-plugin-cc finds a binary instead of offering `npm install -g @openai/codex`; auth is Codex's own (`codex login`).
- **Alfred** — enter the Powerpack licence; point the sync folder at iCloud, which restores workflows, themes and preferences; set the theme for *both* light and dark appearance (the `theme` skill covers the Alfred theme); set the hotkey to `⌘Space`; turn off System Settings → Keyboard → Keyboard Shortcuts → Spotlight → "Show Spotlight search", which otherwise owns that key.

Alfred's config is **deliberately not in this repo**. Its sync folder moves the whole `Alfred.alfredpreferences` bundle — app-owned mutable state that Alfred writes to directly, which is a different model from the declarative source the rest of the repo holds. iCloud handles it instead. The licence, clipboard database and usage data sit *outside* that bundle, so nothing secret travels with it.

**Do not try to disable the Spotlight hotkey declaratively.** It lives at `AppleSymbolicHotKeys` key `64` in `com.apple.symbolichotkeys`, and `system.defaults.CustomUserPreferences` emits `defaults write <domain> <key> <plist>` — a whole-dict *replacement*, which would wipe the other ~50 hotkey entries (Mission Control, screenshots, input sources…). `PlistBuddy -c "Set :AppleSymbolicHotKeys:64:enabled false"` edits in place and would work, but needs `killall cfprefsd` for the preference cache and would need its own recipe — not worth it for a one-time toggle.

`⌘` combinations never reach programs inside the terminal (macOS handles them at the app layer), so they are the safe modifier for global hotkeys; `⌃` and `⌥` do reach tmux and Neovim — `⌃Space` is already blink.cmp's completion trigger and `⌥hjkl` is mini.move.
